# Problem and intent — CTO Agent and template activation

## Problem

Softwareco has a proved preservation-first Factory Flow pilot, but its company governance still describes the Org Owner and CTO Agent as inactive proposals. The pilot-specific CTO delegation expired, while the L1 agent template still mixes agent-product identity, organizational authority, branch policy, and embedded cognitive-procedure guidance.

The project template already carries strong AK and owner-routing guardrails, but neither template exposes a concise delegation-discovery, finite-WIP, outcome-evidence, external-effect, and terminal-human-decision contract.

Decision 62 deliberately blocked propagation until a materially different second pilot. The human operator has now explicitly changed the desired sequence: activate the recommendations and L1 templates first, then test them in `infra/issue-tracker`.

## Intent

Create one bounded, reviewable Softwareco activation that:

1. names the higher-level human operator as the residual Softwareco Org Owner role;
2. delegates technical flow stewardship to `softwareco-cto-agent` without transferring human-reserved authority;
3. defines a lightweight CTO operating cadence and evidence packet;
4. strengthens the L1 project and agent repository templates;
5. keeps L0 and existing L2 propagation outside this decision;
6. treats `infra/issue-tracker` as a canary that may validate or reject the template changes before broader rollout.

## Success condition

The templates and governance are internally coherent, independently reviewed, deterministically validated, and usable by a cold operator in the issue-tracker canary without creating shadow authority or accidental external effects.
