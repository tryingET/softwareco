# Learning — preservation-first retirement is an owner-routing intervention

## Observation

A dirty, authority-ambiguous repository could be made safely legible without deletion, cleanup, or a new control platform by applying this order:

1. bind a real outcome and human authority;
2. preserve all bytes, Git state, metadata, and lineage outside the source;
3. prove disposable restoration;
4. classify every preserved status entry;
5. change only source-owner routing/status projections;
6. independently test cold-start discoverability;
7. request the human terminal decision.

For `fcos-proving-lane`, the preservation manifest covered 48 status entries and restoration matched exactly. The source transition changed only three owner-doc paths. A clean-context operator then found the native FCOS owner, historical status, no-deletion boundary, and escalation path in 56 seconds without using the stale Factory Flow packet as authority.

## Why it worked

- **Owner-native truth stayed primary.** AK held tasks, decisions, direction, and evidence; the source repo held its retirement projection; FCOS Control Board retained FCOS product authority.
- **Preservation removed pressure to clean first.** Classification could distinguish historical facts, migrations, misplaced evidence, disposable material, and active redirects without destroying any of them.
- **The packet remained a membrane, not a database.** The independent operator succeeded from source-owner and AK evidence even while the pre-ADR packet was stale.
- **Outcome and conformance stayed separate.** Archive/document completeness alone did not prove improvement; the cold-start test did.
- **A non-action can be correct routing.** No FCOS item was created because no active cross-owner gate was required, and no capability-map mutation was needed because existing routing projections did not claim the retired repo as a product.

## Reusable rule

For evidence-rich zombie repositories, prefer **preserve → restore-prove → classify → owner-project → cold-test → human decide**.

Do not begin with delete, reset, broad migration, capability-map editing, or template propagation. If the source is dirty or ownership is disputed, that increases the need for lossless capture; it does not justify cleanup by convenience.

## Limits

This pilot proves one internal evidence-retirement flow. It does not prove:

- human-facing product demand or delivery;
- production release/incident operation;
- physical repository deletion;
- company-wide Factory Flow effectiveness;
- a reusable L2 or L0 template requirement.

Propagation remains blocked until a second materially different human-facing pilot succeeds and a separate template-owner decision accepts the generalized contract.
