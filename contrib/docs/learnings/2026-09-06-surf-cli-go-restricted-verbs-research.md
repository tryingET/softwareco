## 2. Per family

### 2.1 `libgen` (actually Z-Library, domain 1lib.sk)

**Naming.** The group is called `libgen` but the code targets **1lib.sk**, described in-code as "a Z-Library mirror"
(`libgen.go:22-23`). Nothing touches Library Genesis. The site model is documented only in the ANNAS1 diary
(`ttmp/2026/04/16/SURF-20260417-ANNAS1.../reference/01-diary.md`, "Step 6: 1lib.sk (libgen) Commands") and the
LIBGEN1 bug ticket.

**`libgen search --query Q`** (`libgen_search.go`)
1. URL `https://1lib.sk/s/<Q>` built with `fmt.Sprintf`, **no URL escaping** (`:189`).
2. Owned tab with `URLPrefix: "https://1lib.sk/s/"` (`:192-194`), or `navigate` + `waitForTabReady` on a supplied
   tab (`:201-208`).
3. Hydration poll: up to 10 s, every 500 ms, `document.querySelectorAll('z-bookcard.ready').length > 0`
   (`:222-235`).
4. Extraction JS generated by `buildLibgenSearchCode(limit)` (`:70-128`): iterates `z-bookcard.ready` custom
   elements, reads attributes `href`, `id`, `download`, `year`, `extension`, `filesize`, `publisher`, `language`,
   title/author from light-DOM `[slot="title"]`/`[slot="author"]`, and falls back to `card.shadowRoot` →
   `z-cover[title|author]` (`:92-102`). Hash id parsed from `/book/<id>/`. Limit applied inside the JS.
5. Model `libgenBookResult` (`:250-262`); rows `title, author, url, id, numeric-id, download-url, year, size,
   format, publisher, language` (`:321-340`); Markdown numbered list (`:342-378`).
No pagination, no ranking (DOM order), no retry (`withOwnedTabRetry` was never applied to libgen), no rate limiting.

**`libgen download --id|--url [--save-to P]`** (`libgen_download.go`)
1. URL from `--id` → `https://1lib.sk/book/<id>` (`:241-247`); owned tab (`:262-270`); fixed `time.Sleep(2s)`
   (`:292`).
2. Metadata JS (`:73-153`): `h1`/`h2` title, all `a[href*="/author/"]`, book id from `location.pathname`,
   `a[href*="/dl/"]` as the download link with format/size regex on the link text (`:99-111`), then text-scan
   fallbacks on `.bookDetailsBox` and `document.body.innerText` for `Year:` / `File:` (`:113-137`) and any `/dl/`
   href (`:139-149`).
3. With `--save-to`: `expandDownloadPath` (`:319-347`: `$VAR` and `~/` expansion, extension derived from format,
   `MkdirAll 0755`), then `browserDownloadFile` (`:349-429`):
   - `navigate` the tab to the `/dl/` URL so **the browser's own Z-Library session/cookies** perform the download
     (`:354-356`); sleep 3 s.
   - Page check JS (`:155-196`) classifies the landing page by `h1` text: `daily_limit` ("daily limit", "limit
     reached"), `not_found`, and `login_required` when `a[data-mode="singlelogin"]` is **visible** (`isVisible`
     `:178-186`: display/visibility/opacity/offset size). This visibility check is the LIBGEN1 fix (c524c08); the
     original presence-only check produced false positives for logged-in users
     (`ttmp/2026/04/25/SURF-20260425-LIBGEN1.../analysis/01-bug-analysis-....md`, "Root Cause").
   - Error strings tell the user to "log in to your Z-Library account in the browser or wait 24 hours" (`:372-374`).
   - Download-completion watcher: `getBrowserDownloadsDir` (`:431-458`: `$XDG_DOWNLOAD_DIR`, `~/Downloads`,
     `~/downloads`), then up to 60 s every 2 s: if no `*.crdownload` remains, `findRecentFile` (`:460-490`) returns
     the **newest `.pdf/.epub/.mobi/.djvu` modified after "now minus 2 s"**, which is renamed (or copied and removed
     across devices) to the target path (`:413-419`).
4. Rows: `title, author, year, format, size, download_url, id` plus `saved_to` / `error` (`:536-553`). A download
   error is stored in the row, not returned (`:309-313`), so the command exits 0 on download failure — exactly the
   "row with an `error` field exits 0" class the HOSTERR ticket later fixed elsewhere.

**`libgen suggestions|collections --id|--url`, `libgen collection --id|--url`**: same skeleton. `collections`
(`libgen_collections.go`) sleeps 5 s, then loops 8 times: scroll to bottom, sleep 2 s, click every `<button>` whose
text includes "Load more"/"Show more" (`:232-250`), scroll back, sleep 2 s, then parses `<z-booklist href topic
quantity>` with nested `<z-cover title author>` (`:87-108`) and falls back to `a[href*="/booklist/"]`. `suggestions`
(`libgen_suggestions.go:87-160`) parses `<z-book>`, `<z-cover>`, then any `/book/` link. `collection`
(`libgen_collection.go`) opens `/booklist/<id>` (`:188`) and reads `a[href*="/book/"]` (`:99-134`).

**Techniques present**: custom-element/shadow-DOM attribute reading; hydration polling on a `.ready` class;
visibility-aware login detection; page-state classification by heading text; browser-session download with
`.crdownload` polling; scroll + "Load more" loop. **Absent**: domain discovery/rotation (1lib.sk hardcoded ~20
times), retries, rate limiting, error propagation, dry-run, any test.

**Hazards in the code itself**: `findRecentFile` can grab and move an **unrelated** file the user downloaded in
the same window (`:460-490`); unescaped query (`:189`); every `closeOwnedTab` error is ignored; fixed sleeps.

### 2.2 `annas-archive`

**Files.** `annas_archive.go` (parent, does nothing itself `:56-67`), `annas_archive_search.go`,
`annas_archive_download.go`. Scripts: `annas_archive_search.js` (embedded, `_search.go:23-24`);
`annas_archive_download.js` (embedded at `_download.go:27-28` but **never used** — the download flow builds all JS
inline: `buildMetadataCode` `:130-173`, `buildMirrorListCode` `:176-254`, the wait poll `:427-474`);
`annas_archive.js` (351 lines, orphan, a dual-mode search/SciDB extractor ending in `console.log` + bare
expression, i.e. the pre-`return` prototype from the ticket) and `annas_archive_minimal.js` (14 lines, orphan).
Ticket ANNAS1 keeps four probe scripts and a 397-line diary.

**`annas-archive search --query Q [--max-results N]`** (`_search.go`)
1. URL `https://annas-archive.gl/search?q=<esc>&index=journals` (`:78-80`, papers index only).
2. `withOwnedTabRetry` with defaults (retry 1, 500 ms) (`:151-164`, migrated in 3bf2cd1).
3. `annas_archive_search.js`: query from URL (`:8-10`); results container = first child of `main` whose text
   contains "Results 1-" (`:19-34`); total from `Results N-M (T total)` (`:36-41`); `a[href^="/md5/"]` de-duplicated
   by md5 (`:44-54`); title = first sibling link with >30 chars that is not a date (`:56-69`); **format/size/year
   are regex-matched on the whole container text, so every result gets the same values** (`:79-89`); hard cap 20
   (`:101`). `--max-results` (`_search.go:64`) is declared but never passed to the script
   (`buildAnnasArchiveSearchCode` returns the script unchanged, `:82-84`).
4. Rows: `query`, `totalResults` + per-item `md5, href, title, format, size, year` (`:203-231`); Markdown
   (`:233-295`) prints `https://annas-archive.gl<href>`.

**`annas-archive download --doi D [--list-mirrors] [--mirror slow] [--mirror-index i] [--save-to P]`**
(`_download.go`)
1. DOI normalised (`:100-105`, strips `https://doi.org/`); navigate owned tab to
   `https://annas-archive.gl/scidb/<doi>/` (`:317-337`); sleep 2 s.
2. `buildMirrorListCode` (`:176-254`): on a SciDB page finds the `/md5/<32 hex>` record link; on any page collects
   `a[href*="/fast_download/"]` and `/slow_download/` links, parses the trailing server index, de-dupes, sorts,
   reads the DOI link. `parseMirrorResponse` (`:540-590`) swallows errors into an empty struct.
3. Navigate to `/md5/<md5>` (`:359-368`), sleep 2 s, `buildMetadataCode` (`:130-173`): title from `h1/h2`; DOI,
   year (**first 19xx/20xx in body text**), format (`PDF|EPUB|CBZ`), size by regex on `document.body.innerText`.
   Re-run the mirror list.
4. `--list-mirrors`: one row per mirror `type, index, label, url` (`:625-639`); Markdown lists "Fast Mirrors (12
   available)" and "Slow Mirrors (8 available)" (`:655-683`).
5. Download mode: `--mirror fast` is refused with "fast mirrors require Anna's Archive membership" (`:409-412`,
   commit 81eeafd "fail fast for fast mirrors"). `getMirrorURL` (`:108-127`) picks a **random** slow server
   `rand.Intn(8)` unless `--mirror-index` is given and builds `/slow_download/<md5>/0/<i>`.
6. Navigate there and poll for up to 120 s every 3 s (`:422-498`) with inline JS that classifies the page:
   `waiting` if body text includes "please wait"/"generating"/"preparing" (extracts "N seconds/minutes" for a debug
   line on stderr), `download_page`, or `found` when an external (`!startsWith('/')`) link contains `.pdf` or `/d3/`
   or its text contains "download". The diary records the resolved URL shape
   `https://b4mcx2ml.net/d3/x/.../paper.pdf` (`reference/01-diary.md:167`).
7. `--save-to`: `downloadFile` (`:720-773`) fetches the URL with a plain `http.Client{Timeout: 300s}` **from the CLI
   process** (no browser, no cookies, Go's default User-Agent), `MkdirAll 0755`, writes the file, forces `.pdf`,
   `sanitizeFilename` (`:776-785`).
8. Output row: `md5`, metadata keys, `download_url` (`:641-652`); Markdown with the raw URL in a code block
   (`:685-717`).

**Techniques present**: DOI → record → partner-server resolution chain; enumeration of numbered partner servers
("mirrors") and random selection; paywall fail-fast; countdown/wait-page polling with page-state classification;
external-link heuristics; direct HTTP retrieval after in-browser resolution. **Absent**: domain rotation
(`annas-archive.gl` hardcoded ~10 times; the site rotates TLDs and is blocked in several countries, so the code is
likely already dead), rate limiting beyond the site's own wait pages, retries on the download path, tests. Oddities:
broken indentation at `:42` and `:500`; `--mirror list` accepted as an alias (`:395`).

### 2.3 `upwork`

**Scope.** Thirteen verbs in three groups: read-only extraction (`jobs`, `job`, `proposals`, `proposal`,
`freelancer`, `client`, `portfolio list`), a two-phase bid workflow (`bid-prepare`, `bid-apply`), and portfolio
mutation (`portfolio create|update|delete`). All require "a browser already signed into Upwork" (help text
throughout). Constants: `upworkHostPrefix = "https://www.upwork.com"`, search path `/nx/search/jobs/`
(`upwork_jobs.go:27-28`).

**`upwork jobs --query Q [--page N] [--sort s] [--job-type hourly|fixed|both] [--experience ...] [--min-rate..]
[--max-results N] [--retry-count N] [--retry-delay-ms N] [--allow-empty-results]`** (`upwork_jobs.go`)
- URL builder `buildUpworkJobsURL` (`:142-191`) maps flags to **server-honoured** query parameters validated live on
  2026-07-11: `t` (0 hourly / 1 fixed / "0,1"), `contractor_tier` (1/2/3), `hourly_rate` and `amount` as `lo-hi`
  ranges (`upworkRangeParam` `:124-137`), `page`, `sort`; invalid values are errors (`:161-162`, `:173-175`). Tested
  in `upwork_jobs_test.go:13-54`. Pagination is one page per invocation.
- `upwork_jobs.js`: `isChallenge` (`:34-36`, title "Just a moment..." or `#challenge-running`/`#cf-challenge-running`)
  treated as not-ready, `detectLoggedIn` (`:28-32`: logged out iff both a `/ab/account-security/login` and a signup
  link exist), `CARD_SELECTOR = 'article.job-tile, article[data-test="JobTile"]'` (`:22`), per-card `data-test`
  anchors (`:52-101`: `job-tile-title-link`, `job-type-label` split into type+rate `:40-50`, `token`,
  `job-pubilshed-date` [sic, Upwork's own typo], `proposals-tier`, `experience-level`, `duration-label`,
  `payment-verified`, `JobDescription`), referrer query stripped and `~id` parsed (`:59-68`), de-dupe by URL
  (`:103-118`), and a 30 s `waitForCondition` that succeeds on tiles **or** an explicit no-results phrase
  (`:120-144`); otherwise it throws "No Upwork job tiles found (page may be blocked by a Cloudflare challenge or
  require login)".
- Go: owned-tab path uses `withOwnedTabRetry` with `isUpworkTransientErr` (`:250-273`: CDP "navigated or closed",
  the tiles-not-found message, and the zero-rows message) (`:308-331`); supplied `--tab-id/--window-id` path
  re-navigates in place per attempt and never closes (`:336-400`); `enforceUpworkJobsInvariant` (`:406-415`) makes
  zero rows a non-zero exit unless `--allow-empty-results`. Rows carry `query, href, loggedIn, jobCount` plus card
  fields with `skills` joined (`:434-468`); Markdown truncates descriptions at 500 chars (`:562-567`) and prints a
  "Not logged in" note (`:489-491`).
- The CDP async-evaluate timeout was raised 10 s → 35 s globally so it exceeds this 30 s poll
  (`src/cdp/controller.ts`, commit 3ca3fde).

**`upwork job <url>`** (`upwork_job.go`): `normalizeUpworkJobURL` (`:80-101`) accepts absolute upwork.com URLs or
`/jobs/...` paths, strips the referrer query, rejects search URLs. `upwork_job.js`: title from `document.title`
minus trailing category (`:36-40`); client stats by anchored regex on `[data-test="about-client-container"]`
(`:45-63`: payment/phone verified, rating, total spent, hire rate, jobs posted); budget by regex on body text
(`:67-82`); not-found detection (`:29-32`); "Activity on this job" block (`:124-131`: proposals, interviewing,
invites, unanswered, last viewed, hires), bid range High/Avg/Low (`:132-133`), `connectsToBid` and
`availableConnects` (`:134-135`). Row flattens `client.*`, `activity.*`, `bidRange.*` (`upwork_job.go:218-253`).

**`upwork bid-prepare <url> [--out F] [--cover-letter S] [--keep-tab-open]` and
`upwork bid-apply --file F [--submit] [--tab-id N]`** (`upwork_bid.go`, `upwork_bid.js`)
- `normalizeUpworkApplyURL` (`:34-57`) turns any job/apply URL into `/nx/proposals/job/~<id>/apply/`.
- `buildUpworkBidCode(mode, coverLetter, rate, answers, submit)` (`:68-81`) → `const SURF_OPTIONS = {...}` prelude.
- `runUpworkBidScript` (`:86-163`): with an explicit `--tab-id` it **never navigates** ("Reloading the apply page in
  an automated tab intermittently bounces Upwork to its login page", `:116-118`); with a window it navigates; else it
  opens a fresh owned tab and retries up to 3× on failure, closing bounced tabs (`:136-162`).
- Template file (`writeUpworkBidTemplate` `:186-209`): comment header with the two invocation lines, `url:` and
  `connects_cost:` headers, `[rate]`, `[cover_letter]`, `[question:N] <label>` sections; parser
  (`parseUpworkBidFile` `:211-298`) requires a `url:` and a non-empty cover letter. `bid-prepare` writes it to
  `--out` or `os.TempDir()/upwork-bid-<jobid>.txt` with mode **0644** (`:380-386`) and prints the tab id for reuse.
- `bid-apply`: `--submit` defaults to false (`:459`); the Markdown report shows `coverLetterMatches`, answers filled,
  `unfilledRequired`, `submitted`/`submitError`, and explains that a closed tab loses the draft (`:517-571`).
- `upwork_bid.js`: readiness = a textarea **and** the Connects indicator (`:105-125`), explicitly not the submit
  button (lazy-rendered below the fold); login-bounce detection (`isLoginBounce` `:30-32`, throws
  `UPWORK_LOGIN_BOUNCE` `:130-132`); Cloudflare wait; fixed 3.5 s settle then a stable-textarea-count streak (6 × 500
  ms) (`:134-154`); `classifyFields` labels textareas by walking up to six ancestors for a label-like node
  (`:56-96`); `setNativeValue` calls the prototype `value` setter and dispatches `input`/`change`/`blur` so Angular
  bindings update (`:34-43`); rate via `[data-test="up-fe-rate-widget"] input[data-test="currency-input"]`
  (`:98-103`); extract mode returns `connectsCost, ratePrefill, questions[]` (`:161-171`); fill mode sets cover
  letter, answers, rate, then **only if `submit`**: refuses when any required field is empty, finds the button whose
  text matches `/submit proposal/i` (`:45-49`), refuses if missing/disabled, clicks, and waits 15 s for the URL to
  leave `/apply` or a confirmation phrase (`:196-223`).
- **Incident recorded in the ticket.** While setting the "Bid to boost" amount, clicking the boost section's
  "Set bid" button **submitted a real proposal** (rate $85, cover letter, four answers, boost 132 Connects, ~150
  Connects total) although the session was meant to be draft-only
  (`ttmp/2026/07/11/SURF-20260711-UW1.../reference/02-implementation-diary.md:96-98`). The resulting rule
  (`reference/01-upwork-page-analysis-and-verb-design.md:146-152`): setting any value must never click a form-level

  `scripts/13-set-boost-bid.js`, still clicks "Set bid" (`:88-94`) and is kept "for traceability". A `--boost` flag
  remained TODO.

**`upwork proposals [--max-results N]`** (`upwork_proposals.go`, `upwork_proposals.js`): opens `/nx/proposals/`

**`upwork client <job-url|~id>`** (`upwork_client.go`, `upwork_client.js`): Upwork has no public client profile, so

(`:59-122`) requiring a `$` amount, extracting title, amount paid, rate, hours, period, rating and the

**`upwork portfolio list|create|update|delete --profile-url <own profile>`** (`upwork_portfolio.go`,
`upwork_portfolio_create.go`, four scripts)
- Shared runner `runUpworkPortfolioScript` (`upwork_portfolio.go:46-95`) opens the profile in an owned tab and closes
  it only when `closeOnDone` (list, delete); `portfolioPrelude` (`:97-103`).
- `list` (`upwork_portfolio_list.js`): tiles are located by walking up from each "More options" button (`:32-55`)
  because Upwork exposes no tile id; items are **title-keyed**; optional Published/Drafts tab click (`:70-76`); page
  info "N of M".
- `create` (`upwork_portfolio_create.js`): waits for the profile, clicks the button with `aria-label` "Add portfolio"
  (`:66-72`), fills `textarea/input[aria-label="Project title|Project description|Your role (optional)"]` with
  `setNativeValue` (`:80-85`), best-effort skill autocomplete (type, wait 900 ms, click first `[role="option"]` or
  press Enter, `:87-107`), and only with `--save-draft` clicks the button whose text starts with "Save as draft"
  (`:116-134`); Go closes the tab only after a confirmed save (`upwork_portfolio_create.go:178-186`); help text
  states it "never publishes" (`:65`).
- `update` (`upwork_portfolio_update.js`): finds the tile by case-insensitive substring `--match` (`:59-79`), opens
  its menu, clicks "Edit" (`:82-91`), fills the given fields and **leaves the form open** — it deliberately does not
  drive the "Next: Preview" republish flow (`:96-112`; `upwork_portfolio.go:261`, `:301-302`).
- `delete` (`upwork_portfolio_delete.js`): without `--confirm` it only reports the match (`:70-77`); with it, menu →
  "Delete" → confirm button inside `[role="dialog"]` excluding "Cancel" → waits 15 s for the tile to disappear
  (`:79-113`).
- PORTMEDIA (`ttmp/2026/07/13/SURF-20260713-PORTMEDIA.../design/01-...md`) designs image/video/PDF upload via
  `DataTransfer` → `input.files` or a synthetic `drop` event with bytes passed as base64 in the options blob

## 4. Exposure assessment

### 4.1 Copyright: the shadow-library verbs

**What the code does, factually.** `libgen download --save-to` drives the user's logged-in **Z-Library** account in
the browser to a `/dl/` link and harvests the resulting file from `~/Downloads`; `annas-archive download --save-to`
resolves a DOI through Anna's Archive to a partner-server URL and fetches the PDF over plain HTTP from the CLI
process (Go's default User-Agent, the workstation's IP). Both verbs recognise the sites' throttles ("daily limit",
"please wait N seconds") and either stop or wait; they do not circumvent them, and fast/member servers are refused.

**Status of the sites (analyst's knowledge; verify).** Z-Library's clearnet domains were seized by the US DOJ in
November 2022 and two alleged operators were indicted; the project has since moved between replacement domains
(1lib.sk being one), several of which were seized again or replaced by look-alike phishing sites. Anna's Archive is
an aggregator/mirror of LibGen, Z-Library, Sci-Hub and other corpora; it rotates TLDs (`.org`, `.se`, `.li`, `.gl`
among others), is blocked by court or regulator order in several jurisdictions, and was sued by OCLC in the US over
WorldCat scraping (filed January 2024; a default judgment followed). A hardcoded `annas-archive.gl` or `1lib.sk`
therefore carries a second, non-legal risk: **the domain can change hands**, and the verbs would navigate the user's
logged-in browser (libgen) or send a CLI request (Anna's) to whoever holds it.

**German law (operator is in Germany).**
- §53(1) UrhG allows private copies only if the source was not "offensichtlich rechtswidrig hergestellt oder
  öffentlich zugänglich gemacht". Shadow libraries are the textbook case of an obviously unlawful source, so
  downloading a book or paper from them is a reproduction (§16 UrhG) without a licence or exception.
- The research exceptions (§60c UrhG and the §60a ff. family) permit reproductions for non-commercial research
  within limits, but are generally not read as legitimising copies drawn from obviously unlawful sources; do not rely
  on them for these verbs.
- Civil exposure: injunction, damages and reimbursement of warning-letter (Abmahnung) costs under §97, §97a UrhG.
  Criminal exposure exists on paper (§106 UrhG) but is rarely pursued for pure downloading; the German enforcement
  industry concentrates on peer-to-peer *uploads*, which these verbs do not perform. The download still leaves the
  workstation IP (Anna's) or a named account (Z-Library) in the counterparties' logs.
- On a company machine the company is the connection holder that receives any notice; the 2017 TMG changes limit
  access-provider liability but do not exempt the person who copies.
- Lawful alternatives for the paper use case exist and cover most of the need: DOI content negotiation, Unpaywall /
  OpenAlex open-access lookups, arXiv/publisher OA versions, library access.

### 4.2 Platform terms: Upwork and freelancer.com

**Upwork.** The Terms of Use / User Agreement prohibit accessing the site by automated means (bots, scrapers,
crawlers) without written permission, prohibit collecting other users' information, and require that a freelancer's
proposals and profile content be their own. Upwork publishes an official API (GraphQL, key subject to approval) as
the sanctioned integration path; none of these verbs use it. The code interacts with Cloudflare bot management by
waiting through the interstitial (`upwork_jobs.js:34-36`; help text: "transparently passing the Cloudflare
interstitial", `upwork_jobs.go:76`) and treats the intermittent redirect of automated apply-page loads to
`/ab/account-security/login` as a flake to retry around (`upwork_bid.go:136-162`, diary `:90-91`); that redirect is
consistent with the platform detecting automation, though the ticket does not establish the cause. Enforcement is
administrative: warnings, suspension or permanent closure of the account, which on Upwork means loss of the earnings
history, Job Success Score, pending Connects and access to escrowed contracts. Financial exposure is concrete and
already materialised once: the accidental submission cost ~150 Connects (diary `:96-98`), and `bid-apply --submit`
sends a proposal to a real client on each run.

**freelancer.com.** Its Terms and Conditions likewise prohibit automated access and scraping. The three implemented
verbs read public pages only and mutate nothing, so account risk is lower, but systematic extraction of listings
also raises the sui-generis database right (§87a ff. UrhG) question for the platform's listing database; the fork's
own roadmap kept bidding out of scope.

**Personal data of third parties.** `upwork freelancer` and `upwork client` extract named individuals' locations,
rates, earnings, ratings and work history and shape them as rows "for database upsert" (`upwork_client.go:59`).
Storing such rows in our systems would need an Art. 6 GDPR lawful basis and, if retained, Art. 14 information
duties, independent of the platform's ToS prohibition on collecting user information.

### 4.3 Personal data and secrets handling in the code and repo

- **No credentials are stored or handled** by any of the four families; every verb relies on the user's existing
  browser login (Z-Library, Upwork). No cookie export or token handling exists in these files (the ChatGPT provider's
  cookie transfer noted in the deep dive is out of scope here). Anna's Archive needs no login for the slow path.
- **Bid templates are written to `os.TempDir()` with mode 0644** (`upwork_bid.go:380-386`) and contain the cover
  letter and screening answers; on a multi-user host they are world-readable. `--out` moves them elsewhere.
- **Downloaded files** go to `--save-to` (`MkdirAll 0755`) or are moved out of `~/Downloads`; the libgen mover can
  pick an unrelated recent file (§2.1).
- **`--debug-socket`** prints full request/response frames, including extracted page content, to stderr.
- **Personal data committed in the archive:** `ttmp/2026/07/11/SURF-20260711-UW1.../scripts/11-bid-a-filled-template.txt`
  is a real, filled proposal for job `~022075805338486027547` with the author's cover letter, four screening answers
  describing his projects and repositories, a rate of $85 and "US Eastern (Providence, RI)" (`:44`);
  `10-bid-a-cover-letter.txt` duplicates the letter; the diary records his Connects balance and the submitted
  proposal; `.envrc` and the LIBGEN1 analysis embed `/home/manuel/...` paths; the ANNAS1/LIBGEN diaries name the
  DOI and book titles used for testing. These are the author's own data, published by him under MIT, but they are
  personal data in our copy.

## 5. Recommendation

1. **libgen and Anna's Archive: never run, never port, never redistribute.** The verbs are unlawful to use from
   Germany for copyrighted works (§53(1) UrhG), point at domains that change hands, have zero tests, and contain a
   file-moving heuristic that can damage the user's own downloads. Nothing in them is needed: their only reusable
   ideas (visibility-aware login check, download watcher, wait-page polling, shadow-DOM reading) are one-paragraph
   mechanisms to re-implement from the descriptions in §3, not code to copy.
2. **Upwork: never run against a real account; treat as reference only.** Automated access conflicts with the
   platform terms, the login bounces suggest the automation is visible, and the write verbs spend money or delete
   content. If a marketplace integration is ever wanted, the official Upwork API is the route. The **engineering**
   in this family is the most valuable of the four: the prepare/apply split, the typed negative readiness states,
   the invariant + retry design, the incident-derived "never click a form-level button" rule and the socket-level
   retry test are worth borrowing verbatim as ideas (§3 rows 1-8, 12, 15).
3. **freelancer.com: reference only.** Read-only and low-risk, but still against the site's terms and superseded in
   value by the Upwork family's more mature versions of the same patterns.
4. **Concrete borrowing, with attribution "Nico Bailon / Manuel Odendahl, surf-cli (MIT)":**
   - a shared page-side helper header (`sleep`, `normalizeText`, `waitForCondition`, `setNativeValue`,
     `isChallenge`-style typed negative states, `labelFor`) for Claude-in-Chrome `javascript_tool` and `surf js
     --file`, written fresh and site-agnostic;
   - a TIP "agent-driven form mutation safety" distilled from `upwork_bid.go`/`upwork_bid.js` and UW1 §5.2:
     read step writes an editable artifact, write step defaults to fill-only, explicit `--submit`, refuse on empty
     required fields, click only the intended button by text, verify the post-condition, never replay mutations;
   - the zero-rows invariant and transient-error retry as a Pi tool result contract (relevant to
     `owned/test-capabilities`).
5. **Archive hygiene.** Keep `contrib/surf-cli-go` read-only and unexecuted. Decide explicitly whether the
   archive copy must stay byte-identical or whether the UW1 bid artifacts (personal data) should be removed; either
   way, never copy files from `libgen_*`, `annas_archive_*`, `upwork_*`, `freelancer_*` or their scripts into an
   owned repository.
